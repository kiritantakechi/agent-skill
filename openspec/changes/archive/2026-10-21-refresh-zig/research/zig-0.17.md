# Zig 0.17.0 audit of `skills/zig-style`

**Scope.** Section 2 of SKILL.md is the reality check. Two questions: what 0.17 broke in that section and in the rest of the skill, and, more important, what 0.17 deprecated that still compiles. I made no repository edits.

**How I checked**
- **Release notes.** I downloaded the 0.17.0 release notes, converted them with pandoc, and read every section from Target Support through Roadmap.
- **std diff.** I diffed every `pub` declaration and every `Deprecated` doc comment between the 0.16.0 and 0.17.0 std trees.
- **Name resolution.** I resolved all 379 distinct `std.…` names the skill mentions, on both compilers.
- **Verified blocks.** I compiled all 220 `// verified` zig blocks on 0.17, with a force-analysis tail corrected for 0.17. I then ran them again with every top-level decl made `pub`. That second run reaches code the harness never analyses.
- **Probes.** Behavioural claims (fuzz, `zig reduce`, DWARF, fetch, CLI) were run as probes in the scratch dir.

**Path and line conventions**
- `std/…` is `/nix/store/bg372xp0r29mh7qigkbx1gb3j50nnmcl-zig-0.17.0/lib/zig/std/…`.
- `std16/…` is `/nix/store/1yqcgzbny4k5p4b9irn5vw4vy8b5d5dh-zig-0.16.0/lib/zig/std/…`.
- `compiler/…` is `lib/zig/compiler/…` (0.17).
- `RN §X` is a release-note section.
- `show-builtin:N` is line N of `zig build-obj --show-builtin` on 0.17 (aarch64-macos). That module is generated by the compiler, so it has no lib file.
- Block lines follow the harness convention: the first body line, which is the fence line + 1.

**Status values used in the tables**
- **gone**: a compile error on 0.17.
- **alias**: deprecated but still compiles. These matter most, because the toolchain will not catch them.
- **semantics**: compiles, but behaves differently.
- **claim**: prose fact that 0.17 makes false.
- **new**: 0.17 offers a better spelling; nothing is deprecated.
- **cite**: a std file:line that moved.

## 0. Harness facts that bear on this change (observed only, not edited)

1. **The force-analysis tail fails on 0.17.** `src/agent_skill/lang/zig.py:30-39` (`FORCE_ANALYSIS`) loops over `@typeInfo(@This()).@"struct".decls` / `__zs_decl.name`. On 0.17 every block then fails with `no field named 'decls' in struct 'lang.Type.Struct'`.
   - 0.17 spelling: `for (@typeInfo(@This()).@"struct".decl_names) |__zs_decl_name| { _ = &@field(@This(), __zs_decl_name); }`
   - With that tail I reproduce exactly your 11 failures.
2. **The tail only reaches `pub` declarations.** `decl_names`, like 0.16's `decls`, lists only `pub` declarations. A non-pub fn or const in a block is analysed only if a test that runs reaches it. The harness skips tests for blocks with an `extern fn` (`lang/zig.py:105`). Making top-level decls `pub` exposes **4 more verified blocks that fail on 0.17**, plus one generic fn that is never instantiated (D.2).
3. **0.16 pins in the harness.**
   - `ZIG_VERSION = "0.16.0"` at `lang/zig.py:23`.
   - "moves past 0.16.0" at `profiles/zig_style.py:39`.
   - The ZS-MIG-13 fixture `EnumSet(Color).initEmpty()` at `profiles/zig_style.py:67` is now a removed spelling. It is still a fine fixture for the grep.
4. **SKILL.md blocks are never compiled.** `Skill.chapters` covers only `references/*.md` (`model.py:579-584`).
   - SKILL.md:79 is not `zig fmt` clean on 0.16 either: aligned trailing comments on lines 84-85.
   - SKILL.md:128, 164 and 177 are snippets that do not compile standalone on either version.
   - I checked the §2 snippets with wrappers on 0.17. They work.

### C.2 What a 0.17 reality check should say

**(a) Silent or wrong-output changes. These come first, because no build fails.**

1. **The optimize mode was renamed.** The tags are `.debug`, `.safe`, `.fast`, `.small`, and `@import("builtin").mode` is now `.optimize`.
   - Old names still work as decl literals and switch prongs.
   - `builtin.mode == .Debug` is a compile error.
   - `@tagName`/`{t}` of a mode now prints `debug`/`safe`. Generated artifact names and log lines change. ZS-TEST-27's `b.fmt("test-{t}", .{mode})` is one example.
   - Prefer `builtin.optimize.runtimeSafety()` over hand-switching and over `std.debug.runtime_safety`. Evidence: E-opt, E-bmode, E-rs.
2. **`mem.containsAtLeastScalar` swapped its last two parameters** to `(T, list, element, minimum)`. 0.16 code that called it with `(minimum, element)` can still compile and silently compute something else. Evidence: E-cals.
3. **`@hasDecl` is now true only for `pub` declarations**, even within the same file. `if (@hasDecl(@This(), "x"))` feature detection over private decls flips silently. Evidence: E-hasdecl.
4. **`@bitCast` changed meaning.**
   - On arrays and vectors it is now logical-bit and endian-agnostic, which differs from 0.16 on big-endian targets.
   - `extern struct`/`union` casts are rejected.
   - Casts to an enum are allowed but safety-checked.
   - Evidence: E-bitcast.
5. **`mem.eql`/`findDiff` on float slices no longer treat the same slice as equal** when it contains NaN. Evidence: E-eql.
6. **`init.gpa` and `std.testing.allocator` are now SafeAllocator.** `init.gpa` is SafeAllocator in Debug and ReleaseSafe even when linking libc; 0.16 ReleaseSafe+libc used `c_allocator`. The allocation profile of a ReleaseSafe binary changes. Evidence: E-gpa.
7. **`zig fmt` rewrites `@intFromEnum`/`@enumFromInt`.** A `zig fmt --check` CI gate goes red on code that has not changed. The rewrite inserts a redundant `@intCast` in `@fromBackingInt` when the operand already has the backing type. Evidence: E-be.
8. **Build-system behaviour changes that still compile.**
   - `addPassthruArgs()` makes the run step uncached, and build scripts can no longer observe the args.
   - A bare `zig fetch` no longer populates `zig-pkg/`.
   - `b.dependency` now accepts lazy packages.
   - Evidence: E-args, E-pkg, E-lazy.

**(b) Loud changes common enough to name in §2.**
- `b.args` is gone; use `addPassthruArgs()`.
- `addFmt(.paths)` takes `b.pathList(&.{…})`.
- `b.build_root` → `b.root` (a `Cache.Path`).
- `b.reference_trace` is gone.
- `LazyPath.getPath*` is gone, so there is no path resolution in configure.
- `@typeInfo` is struct-of-arrays.
- `errdefer |err|`, `**`, `void{}`, `i0` and `@cImport` are removed.
- `std.zon.parse` takes an options struct with a required arena and diagnostics.
- The 0.16 aliases that are now removed (A.2).

**(c) Tooling facts that changed.**
- `zig build test --fuzz` and `zig reduce` work again, so ZS-BUILD-35 expires.
- The new ELF linker emits DWARF.
- `-fincremental --watch` is now usable on x86_64-linux (RN §Incremental Compilation).
- **No ZLS works with 0.17.0.**
- `zig build` CLI flags changed (E-help).
- `zig fmt --complexity` is new.
- LLVM 22 still has loop vectorization off.
